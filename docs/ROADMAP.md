# QuantWatch 完全体路线图

## 产品目标

QuantWatch 将从当前的云端信号看板扩展为**多资产量化研究终端**。它以统一资产标识、标准 OHLCV 数据模型、可组合指标管线、策略描述协议和可复现回测输出为基础，同时覆盖股票、ETF、基金、加密资产，并保留未来接入外汇、商品、期权和地区性市场的能力。

产品的“完全体”并不意味着把全世界的实时市场数据复制进一个数据库，而是意味着：任何经过授权的数据源、资产类别、指标或策略，都可以被按统一协议接入、查询、可视化、回测和扫描。数据覆盖范围由用户的市场数据授权和供应商套餐决定；策略库采用模块化注册机制，而不是将策略逻辑硬编码到前端。

## 分阶段交付

| 阶段 | 交付物 | 初始范围 | 后续扩展方式 |
| --- | --- | --- | --- |
| 第一阶段：研究工作台 | 多资产目录、标的搜索、K线/成交量、指标图层、策略选择器、研究说明 | 美股/ETF/主流加密资产的演示数据和统一数据协议；SMA、EMA、RSI、MACD、布林带、ATR、随机指标、ADX、VWAP | 新资产/新指标以注册表新增，不更改图表框架 |
| 第二阶段：真实数据与回测 | 供应商适配层、密钥保护、OHLCV 缓存、单标的轻量回测、策略参数 | 一个统一市场数据供应商 + 可选加密数据源；日线与有限分钟线 | 增加供应商适配器、资产解析器、缓存策略与历史档案 |
| 第三阶段：策略与扫描 | 预置策略库、自定义参数、市场扫描、条件告警、组合观察列表 | 趋势、均值回归、突破、波动率、动量等策略族；核心资产池 | 扩展为策略插件、批量扫描队列和数据授权市场池 |
| 第四阶段：专业研究 | 多市场历史库、组合层回测、风险归因、因子研究、导出与审计 | 取决于数据许可和计算资源 | 接入外部计算、商业数据源与长期分区存储 |

## 统一数据模型

所有行情适配器输出以下规范对象：

```text
Instrument: { id, symbol, name, assetClass, exchange, currency, providerSymbol }
Candle:     { time, open, high, low, close, volume }
Series:     { instrument, interval, timezone, source, dataMode, candles }
Signal:     { strategyId, side, score, parameters, generatedAt, evidence }
Backtest:   { strategyId, parameters, period, trades, equityCurve, metrics, assumptions }
```

`dataMode` 必须明确标识为 `demo`、`delayed`、`end_of_day` 或 `realtime`。前端不得把演示数据或延迟数据表述成实时行情。

## 策略库边界

首批策略族包括均线趋势、均线交叉、RSI 均值回归、MACD 动量、布林带均值回归、Donchian/Turtle 突破、ATR 波动率突破、随机指标反转和成交量确认。后续可以增加跨资产动量、配对交易、因子选股、统计套利和机器学习研究模板，但每个策略必须提供参数、适用市场、交易假设、风险条件、信号解释和回测限制。

策略研究输出仅用于分析和教育目的，不会自动下单，也不构成投资建议。

## 云端职责划分

| 层级 | 职责 |
| --- | --- |
| GitHub Pages 前端 | 图表渲染、指标计算、策略参数交互、轻量单标的研究与可视化 |
| Cloudflare Worker | 数据源代理、CORS、密钥保护、接口节流、短期缓存、资产目录和研究快照 API |
| D1 / KV / R2 | 资产目录与元数据、热缓存、OHLCV/回测档案及研究快照 |
| 外部数据与计算层 | 经授权的实时/历史数据、批量同步、全市场扫描、重型回测和参数寻优 |

## 数据授权原则

公开仓库不得出现 API Key、供应商密钥或交易所凭据。任何供应商密钥只保存为云端密钥。股票、基金和加密资产的可显示范围、实时性、历史深度和再分发权利取决于实际供应商合同与交易所许可；系统会展示数据来源、数据模式、更新时间和可能的延迟。
